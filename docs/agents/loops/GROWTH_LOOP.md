# Growth and monetization loop

Run one policy-aware, measurable growth iteration without misrepresenting current features or changing active gameplay integrity.

## Inputs

- Stage: `[INTERNAL/SOFT-LAUNCH/CONTENT/ADS-READINESS]`
- One question: `[HYPOTHESIS]`
- Surface/files/actions: `[SCOPE]`

Read `AGENTS.md`, current routes/content, privacy/terms/contact, actual AdSlot/ads.txt behavior, and current official policy for time-sensitive claims.

## Baseline truth

- Quick/Daily share `/play`; Challenge is `/challenge/[token]`.
- No separate Daily archive or Stats page.
- Local persistence is aggregate stats only.
- Offline is a navigation fallback, not guaranteed play.
- No application analytics is implemented.
- Home AdSlot is disabled by default and is only a placeholder when enabled.
- No live AdSense script or consent platform exists.
- Working name is not cleared.

## Gate check

| Gate | Evidence |
|---|---|
| Product | five-round complete story and current score/token behavior pass |
| Accessibility | known keyboard/fluid-target/forced-color issues classified |
| Brand | clearance or private experiment only |
| Content | original useful routes, clear ownership/contact |
| Privacy/legal | launch templates replaced/reviewed for actual services |
| Authorization | exact deployment/posting/submission/account action approved |

## Choose one track

### Activation

Test one home/setup clarification. Preserve rules, square grids, score, deadline, and semantics.

### Challenge sharing

Test share copy or result hierarchy. Preserve `/challenge/[token]`, token privacy, same-seed reproduction, and native-share/clipboard/manual fallback.

### Daily return

Work within current mode/date aggregate behavior. Do not claim canonical first attempts, streaks, or cloud history unless implemented.

### Original search content

Answer one useful question. No mass seed/date pages, keyword stuffing, fake expertise, IQ/medical claims, or guaranteed traffic.

### Analytics readiness

Design only coarse mode/round/family/grid/outcome/score/wrong/error buckets. Exclude seed, token/path, target, descriptors, storage, full URL, and personal text. Implementation requires privacy/consent review and authorization.

### AdSense readiness

Audit current official requirements, content quality, operator/contact, privacy/consent, domain control, placement separation, and performance. Distinguish:

1. current placeholder scaffold;
2. engineering readiness;
3. site/account approval;
4. live serving;
5. uncertain revenue.

Do not submit, set live IDs, add scripts, or enable ads without exact authorization. Keep timed GameShell phases free of ad components.

## Experiment procedure

1. Record baseline and limitations.
2. Write one hypothesis/primary metric and guardrails.
3. Confirm measurement does not need prohibited data.
4. Implement the smallest reversible change in scope.
5. Verify functional, keyboard, responsive, privacy, and performance behavior.
6. If public exposure is not authorized, stop at internal-ready.
7. Apply the predefined decision rule and report.

## Handoff

Report stage/gates, hypothesis, baseline, files/actions, privacy/accessibility/performance guardrails, checks, current status, blocked authorization, and next bounded question. Never promise AdSense approval, traffic, or income.
