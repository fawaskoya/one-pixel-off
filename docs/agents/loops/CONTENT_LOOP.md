# Content and catalog loop

Add one bounded generator-catalog change or one editorial content improvement. Do not mix unrelated tracks.

## Track A — generator catalog

Read exact `catalog.ts`, `generator.ts`, constants, invariants, fixtures, and specs.

Current families: rings, stripes, arrows, corners, dots, diamonds, chevrons, orbit. Current palettes and difficulty arrays are versioned generation inputs. Any order/recipe/candidate/bound/delta/grid change can alter generation version 2.

Procedure:

1. State why the change is needed and whether deterministic output changes.
2. Define integer-only source primitives and exactly one scalar mutation candidate.
3. Keep square `GridSize 4|5|6` and 100-unit view box invariants.
4. Add golden/invariant/family/corpus fixtures.
5. Run generator tests plus typecheck/lint/build as relevant.
6. Stop for approval if a generation bump/migration is needed.

Do not add remote assets, text/logo glyphs, compound mutation, unbounded geometry, retry/fallback claims without code, or invisible subpixel tricks.

## Track B — editorial content

Current indexable routes are `/`, `/focus`, `/play`, `/how-to-play`, `/categories`, `/about`; privacy, terms, contact, challenge, and offline are currently nonindexed support/review routes.

1. Define one real user question.
2. Audit overlap with existing route content.
3. Draft original reviewed copy matching current code: square grids, current score, path challenge, aggregate stats, limited offline fallback.
4. Avoid thin seed/date pages, AI-generated filler, IQ/medical/revenue/clearance promises.
5. Verify metadata, links, semantics, responsive rendering, lint/typecheck/build.
6. Do not publish without authorization.

Report track, files, deterministic/version impact, user value, checks, and unresolved review needs.
